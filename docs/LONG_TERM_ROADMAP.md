# mygpt 长期路线图：从宠物原型到有边界的学习陪伴

- 规划日期：2026-09-22；规划视野：2026-09-22—2027-09-21。
- 文档性质：产品和工程建议，不表示聊天后端、安卓 App 或跨库桥接已经完成。
- 时间口径：以本项目正式启用日 T0 起算；0—30 天等是目标窗口，不是交付承诺。
- 并行原则：全项目同时只有一个主项目、一个支撑项目；本库当前优先作为 Book 的支撑/孵化项目。
- 进入主项目的条件：明确生产宿主、打通一条实际学习链路，并证明陪伴没有增加负担。
- 指标性质：现状表为仓库事实；本文其余数量、阈值与实验规模均为待验证提案。

## 1. 产品定位

mygpt 是具有独立身份的个人学习陪伴与编排层，默认安静，在需要时提供帮助。
它应知道用户正在学习什么、哪些信息可信、何时应询问，而不是从单一行为猜测用户内心。
宠物外观负责呈现状态；宿主负责生命周期；适配器负责接入外部系统；编排层负责何时行动。
不把已有的动画、拖拽与按钮交互等同于完整智能体或生产聊天平台。

基本价值是减少反复解释当前章节的成本、提供合适的复习提示，以及让需要帮助时的入口更自然。
是否有效通过真实学习任务和用户主观负担评估，不以在线时长、推送次数或情感依赖衡量。
现实关系与用户自主选择优先，用户可以随时暂停、隐藏、关闭提醒或改用普通工具。

## 3. 必须保持的职责边界

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| Jonah 渲染组件 | 动画、可访问操作、位置、显隐 | 判断学习状态、储存秘密、调用模型 |
| 生产宿主 | 页面/应用生命周期、导航、设置、会话界面 | 改写 Book 内容权威 |
| Book 适配器 | 校验并接收课程/章节/模式/来源引用 | 猜测缺失章节、复制全书 |
| 会话/活动适配器 | 接收允许的开始/暂停/恢复等事件 | 把静止视为分心、读取私人消息 |
| 对话适配器 | 明确调用、取消、错误、费用记录 | 隐藏重试、绕过提供方权限 |
| 编排策略 | 根据证据决定沉默、询问或提供帮助 | 自动点击其他 App、无限主动打扰 |

Book 继续负责学习内容与学习状态；StudyMate 继续负责其会话与设备信号。
ChatContextVault 是独立受门禁保护的资料库，本规划不读取其内容、不复制聊天语料。
可选 Shadow 必须有独立授权与明显模拟标识，不代表真实人物当前意愿。
当前阶段不实现跨 App 自动控制、持续屏幕采集或背景常开云端推理。

## 4. 阶段 A：T0 后 0—30 天，选宿主、定接口、做最小闭环

### 交付内容

- 比较两个明确候选：移动网页先验证，以及 Android Studio 构建的受限 WebView 宿主。
- 推荐先用已有 Web Component 验证宿主接口；若目标为 Android 交付，再由 Android Studio 建立最小应用壳。
- 一次只选择一个主生产宿主，不同时重写原生 UI 与网页 UI。
- 设计 StudyContext、StudyEvent、CompanionState、ChatRequest 四类最小契约。
- 使用合成事件回放验证行为；没有真实 Book 接入前标明 DEMO/SIMULATED。
- 形成插件式适配器边界和禁用能力列表，渲染组件不直接访问平台凭据。
- 将 #1/#2/#3 的审阅与未来集成顺序写清，不以本规划代替合并授权。

### 契约建议

StudyContext 至少包含 schema_version、session_id、course_id、book_version、section_id、mode 和 source_ref。
事件至少包含 event_id、source、sequence、occurred_at、received_at、type 与经过白名单筛选的 payload。
source_ref 只定位允许使用的来源；实际正文按需由 Book 提供，不全量缓存到 mygpt。
接收方要区分过期、乱序、重复、未知版本和来源断开，不静默使用最后一条旧上下文。
建议先支持 session_started、section_changed、mode_changed、session_paused、session_ended 五类事件。
字段和事件名称是设计提案，不声称现有 Book 已提供这些 API。

### 验收提案

- 至少 50 条事件用例，覆盖正常、重复、乱序、断开、未知版本和缺失来源。
- 同一事件重复 10 次不产生重复主动提醒或重复持久化。
- 上下文过期时明确显示“上下文已断开”，不继续声称知道当前章节。
- 连续 30 分钟模拟学习中，默认无定时催促；用户主动操作始终可触发帮助。
- 隐藏或暂停组件后不继续产生动画负担和自动模型请求。
- 契约由 Book 与 mygpt 两侧共同审查；无生产连接时只验收契约与回放。

### 依赖与停止点

依赖生产宿主选择、Book 当前可提供字段的实际调查和合法开发分支。
没有宿主决定时继续维护组件，不增加大规模模型后台。
没有真实接口权限时使用明确标注的模拟源，不能采用未公开接口绕过产品限制。

## 5. 阶段 B：T0 后 31—90 天，接通一条真实学习帮助链

### 交付内容

- 只接入一门已核验的 Book 课程和一种主要学习模式。
- 支持“这段为什么这样”“给我一个回忆问题”“暂停陪伴”三个明确用户动作。
- 对话请求携带最小上下文、来源引用与有效期，响应展示来源和不确定性。
- 提供取消、超时、失败重试上限及费用记录，不把后台失败伪装成正常等待。
- 若采用 Android 宿主，完成软键盘、返回键、安全区、旋转和生命周期处理。
- 在 Android Studio 中建立可重复构建，并在用户实际设备上验收。
- 对没有答案或来源缺失的情况，能够坦白说明并引导用户补充信息。

### 验收提案

- 至少完成 10 次真实的 30 分钟学习会话，区分代码验证和用户体验记录。
- 抽查 30 个基于当前章节的问题，引用来源正确率目标 ≥95%，无来源不得伪造引用。
- 会话切换、章节切换后不得把上个上下文当作当前事实；此类串线错误为 0。
- 所有用户取消均立即停止界面等待；已发出的远端调用无法撤销时要明确记录实际状态。
- 本地语义事件到宿主状态更新建议 p95 ≤500 ms；模型回复延迟另行测量。
- 安卓实机至少覆盖一次离线、一次进后台和一次软键盘遮挡恢复。
- 不把 WebView 内右下角组件称为系统悬浮窗。

### 依赖与停止点

依赖阶段 A 契约、真实 Book 内容引用和用户选择的可用对话端点。
ChatGPT App 中能对话不自动等于本项目已获得 API 凭据或调用额度。
新的付费调用预算未设置时保持 0；已有本地/订阅/API 成本分别记录。
本规划不购买服务、不提交凭据、不自行开启外部消息发送。

## 6. 阶段 C：第 4—6 个月，让提醒克制且有效

### 交付内容

- 从用户主动帮助扩展到少量可解释的事件触发建议。
- 提醒候选应带理由，例如反复切换同一节、用户明确表示卡住、完成一个学习单元。
- 对静止、离开或延迟响应只询问，不断言懒惰、分心或情绪状态。
- 区分“愿意继续”“稍后提醒”“本次安静”“彻底关闭”四种选择。
- 可选接入 StudyMate 的粗粒度会话事件；不以收集更多权限作为默认进度。
- 建立提醒节流、冷却、重复抑制和断网降级。
- 只在有充分需求时评估跨 App 悬浮窗，单独做 Android 权限与真机里程碑。

### 验收提案

- 至少记录 20 次真实会话；主动提示与用户主动请求分开统计。
- 初始提案：每 30 分钟最多 1 次非用户触发建议，用户明确选择可覆盖该上限。
- 用户点击“本次安静”后，本次会话的主动建议为 0。
- 初始有用率目标 ≥70%；不需要/打扰率 >20% 时回退到仅用户主动模式。
- 用户离开 10 分钟或熄屏时按宿主生命周期处理，不假设拥有持续后台运行能力。
- 连续 10 个关闭/暂停场景中，不发生额外感知上传或主动云端请求。
- 提醒效果不能用学习时长增长单独证明，应结合用户负担与回忆/练习表现。

### 依赖与停止点

没有会话证据就不启用复杂“分心识别”模型。
如果粗粒度事件已足够，不进入屏幕视觉路线。
如果提醒让用户更焦虑或更依赖系统，降低介入强度并重新评估产品目标。

## 7. 阶段 D：第 7—12 个月，形成可恢复、可选择的陪伴系统

### 交付内容

- 稳定支持多个 Book 课程的引用切换，保留各书版本与来源身份。
- 建立用户可见的偏好、提醒策略、记忆摘要和纠错入口。
- 只保存必要的派生学习偏好，不复制完整教材或其他项目原始资料。
- 通过适配器接入更多宿主能力，明确哪些已支持、哪些仅设计。
- 评估语音、跨 App 悬浮窗或会话式视觉回退；每次只选择一个有明确价值的扩展。
- 对长期不用的能力保持禁用，避免持续消耗权限、费用和注意力。
- 完成一次安装/升级/恢复演练与 4 周稳定试用。

### 验收提案

- 2 门课程、4 种学习模式的上下文切换不串书、不串版本；不支持的模式明确提示。
- 用户能查看与修正保存的偏好，错误推断不会被长期当作事实。
- 连续 4 周试用记录请求成功率、提示负担、费用与恢复失败，不只汇总正面反馈。
- 设备重启和版本升级后能恢复允许保留的状态，授权范围不会被自动扩大。
- 若启用视觉，仅处理用户授权的当前会话和指定范围，权限撤销后及时停止。
- optional 扩展无明确增益时不进入正式版，维护好最小学习陪伴链即可验收。

## 10. 指标与成本约束

| 指标 | 口径 | 建议 |
| --- | --- | --- |
| 当前来源正确率 | 人工抽查的问题/引用对 | 初始 ≥95%；伪造引用为阻断项 |
| 上下文串线 | 会话/书籍/版本混用 | 0 |
| 提示有用率 | 用户主动评价的非主动请求建议 | 初始 ≥70%，同时报告无评价样本 |
| 打扰率 | 被标为不需要/打扰的建议 | >20% 回退为用户主动模式 |
| 会话成本 | 模型调用、失败重试与传感成本 | 人民币上限由用户选定 |
| 静音有效性 | 静音后的主动建议/自动调用 | 应为 0，必要状态保存另计 |
| 运行负担 | 真机耗电、温升、内存、启动延迟 | 与无宠物/无模型基线对比 |

计费建议采用单会话上限 C_session 与月度上限 C_month，不能把视觉、语音或失败重试藏在后台预算外。
事件驱动不等于每条事件都调用模型；本地状态变化优先通过规则处理。
未配置的新付费上限为 0；未知费用标 UNKNOWN，不假设免费或已有美元支付能力。
无需在每次常规请求重复询问授权，但不得在授权范围之外悄悄加传感器、扩大数据上传或续费。

## 11. 风险、暂停与退出条件

- main 尚无完整安全治理：不能直接以 main 创建可写应用基线；使用已核验保护分支并由主控处理。
- 宿主不确定：暂停同时开发多个前端，先验证一个完整最小路径。
- Book 接口变化：适配器拒绝不支持版本并提示断开，不能猜测字段含义。
- 上下文过期：不继续回答“你现在看到的内容”，先请求确认。
- 组件遮挡、焦点丢失、软键盘不可用：阻断移动发布，优先修交互。
- 真机权限限制：如实降级，不宣称黑屏持续感知或跨应用悬浮一定可用。
- 费用超过上限：保留会话记录并停止新增付费请求，不能无限自动重试。
- 主动提示没有收益：回退安静陪伴和显式请求，保持产品可用。
- 跨库受保护数据无法访问：停在接口设计，不绕过独立门禁或复制原始语料。
- 连续两月缺乏真实使用：降为维护，避免为“更像 Agent”而增加复杂度。

## 12. 月度复盘与资料分工

每月复盘五项：用户是否少解释上下文、回答是否有来源、提醒是否有用、是否更轻松、费用是否可承受。
每次只决定一个主改进方向，并记录保留、调整、停用或暂缓的证据。
每季度复核宿主选择、模型边界、权限最小化、跨库契约和恢复方式。
GitHub 保存代码、契约、治理和测试索引；Drive 保存构建包、真机材料与必要快照。
Book/StudyMate/ChatContextVault 的原始数据继续留在各自权威系统，不形成 mygpt 的无差别副本。
宠物渲染与对话策略分开版本，避免动画更新触发不必要的模型或权限变更。
同步先对账与哈希去重；不为相同源码重复上传，不自动清理历史证据。
